## Organisation

- Décrire chaque besoin avec le gabarit d’issue **User story**.
- Renseigner les critères d’acceptation, l’estimation en points, la priorité MoSCoW et la Definition of Done (DoD).
- Travailler sur une branche par tâche et ouvrir une pull request pour la relecture.
- Ne jamais versionner de secrets : le fichier `.env` est ignoré.

## Definition of Done commune

- [ ] Les critères d’acceptation sont vérifiés.
- [ ] Le travail a été relu par un autre membre de l’équipe.
- [ ] Les vérifications pertinentes passent.
- [ ] La documentation concernée est à jour.
- [ ] Aucun secret n’est présent dans les fichiers ou l’historique ajouté.

## Mise en route de l’équipe

Le propriétaire invite les trois autres membres dans **Settings → Collaborators**. Chaque membre accepte personnellement son invitation. Les comptes et les rôles du tableau sont ensuite complétés.
